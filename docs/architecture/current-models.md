## Machine profiles (`patmir.toml [pipeline.profiles.<name>]`)

`[pipeline]` above is the Apple-Silicon dev laptop: every model stage runs on MLX. A **profile**
overlays a different candidate per stage so one committed `patmir.toml` serves machines with
different accelerators instead of two working copies diverging on the file that decides which model
runs.

Selected by environment, never autodetected:

```bash
export PATMIR_PROFILE=cuda          # or: patmir bench <clip> --profile cuda
```

Resolution order, last wins:

```
[pipeline]  <  [pipeline.profiles.<p>]  <  code overrides  <  [pipeline.profiles.<p>.<layer>]
```

The `<layer>` tier exists because `streaming/runner.py:streaming_config()` hardcodes MLX-only
candidates as code overrides for watch-along; `[pipeline.profiles.cuda.streaming]` displaces them.
An unknown profile name is a **hard error**, not a fall back to the defaults — on a CUDA box that
would mean quietly trying to load MLX-only candidates. Profiles change `entries`, so each profile
has its own cache key and the two machines cannot serve each other a dub built from a different
model set.

| ------------------- | ------- | --------------------------------------------------------- |
| `stretch_cap`       | 0.20    | Max ±20% time-stretch ratio per sentence (pitch-preserving) |
| `asr_int8`          | true    | ASR runs in int8 quantization when supported              |
| `keep_intermediate` | true    | Don't delete per-sentence WAVs, transcripts, etc. after run |
| `music_bed_gain`    | 0.6     | Accompaniment level under the AR voice (1.0 = unchanged)  |
| `voice_gain_db`     | -3.0    | Global trim on top of the per-sentence RMS loudness match. Negative = quieter. Set to `-3.0` on 2026-05-27 after ear-test on masha-2-5min (default `0.0` was too hot once the per-sentence match was added). |
| `min_ref_seconds`   | 1.5     | Shortest clean turn (after 100 ms edge trim) that qualifies as a `(speaker, emotion)` ref clip. Lowered from 3.0 → 1.5 on 2026-05-27 — ElevenLabs IVC accepts ≥1 s, and 3.0 was excluding most of `SPEAKER_00`'s short cartoon-pace turns on the masha clip. |
| `sentence_afade_seconds` | 0.05 | Per-sentence fade in/out on synthesized track (voice-leak guard, quality issue #4). **The fade-IN is capped at the leading quiet the clip actually has (2026-09-03)**, with a 4 ms anti-click floor: the first line of a job starts within 10 ms in 74% of jobs against 26% for other lines, so the full ramp was chewing the first word's attack (-24.2 dB against the body's -16.3). Fade-out unchanged. Quality issue #30. |
| `ref_min_rms_db`    | -33.0   | Loudness floor (dBFS RMS) for ref-clip windows in `pick_refs` — quiet (far-field/bleed-heavy) slices lose to any louder eligible window; if all windows are quiet the longest still wins. Quality issue #12 (2026-07-14). |
| `[[tts_ref_pool]]`  | (empty) | Top-level table array (not under options): curated stand-in ref clips (`path`, optional `gender`/`text`) for speakers with no usable ref. With no pool configured the TTS adapter reuses another character's pinned ref before ever synthesizing ref-less. Quality issue #12 (2026-07-14). |
| `duck_lead_seconds` | 0.25 | Open the original-vocals duck this many seconds **before** each line's onset. ASR word-onsets land ~0.24s late, so without a lead the original leaked at every line start. Quality issue #9 (2026-06-19). |
| `duck_tail_seconds` | 0.10 | Hold the duck this many seconds **after** each line's end. Quality issue #9. |
| `vocals_bed_gain` | 0.12 | Linear gain on the original vocals stem in gaps **between** ASR sentences (inside sentences the duck zeroes it). Was effectively `music_bed_gain` (0.6); lowered so dialogue ASR missed doesn't leak at full level. 0.0 = fully remove original voice. Quality issue #10 (2026-06-19). |
| `tts_pin_neutral_fraction` | 0.5 | Which clip the per-speaker pin chooses, and it is **not** emotion-neutral: Higgs clones *prosody* from the reference, so pinning an angry clip makes that character deliver the whole film angrily, calm lines included. Plain `max(duration)` did exactly that in **26 of 34 speaker-runs measured** (angry 10, happy 13, sad 3, neutral 8) because nothing was looking at the bin — a much larger contributor to over-emoting (quality issue #15) than the emotion tag, which by then reached ~9% of sentences. Now the neutral clip wins when it is at least this share of the longest clip's length; a much shorter reference clones worse (the timbre drift on #24), so neutrality is not worth any price. On the measured set this takes non-neutral pins **26 -> 11** and angry pins **10 -> 2**. Above 1.0 disables the preference — a neutral clip cannot exceed the longest one — the same "out of range disables it" convention as `duplicate_containment`. Added 2026-09-03, awaiting an ear verdict. |
| `tts_pin_speaker_ref` | true | Pin ONE ref clip per speaker (longest/cleanest, all lines) instead of per-`(speaker, emotion)` ref binning. Keeps each character's cloned voice consistent (per-emotion refs swapped the voice mid-character on cartoon audio). Emotion varies via the TTS candidate's own control — an inline `<|emotion:..|>` tag on the Higgs candidates. (This row used to say "via `[emotion_guidance]`"; that table was **deleted 2026-08-24** after it was found to have been inert since the Higgs swap on 2026-06-20 — the adapter cannot pass `guidance_scale` to a candidate that does not accept it. Quality issue #15.) `false` restores Phase-2.x binning. Quality issue #11 (2026-06-19). |
| `voice_no_overlap`  | true    | Mux never starts a line before the previous line's audio ends (ripples it later). Fixes same-speaker pile-up when TTS is longer than the source slot; drift resets at each speech gap. Quality issue #8. |
| `voice_overlap_gap_seconds` | 0.06 | Minimum silence inserted between consecutive lines under `voice_no_overlap`. |
| `voice_max_compress` | 1.5    | Max pitch-preserving speed-up applied to a line to fit it before the next (with `voice_no_overlap`), so dense dialogue is absorbed by compression + small shift instead of large drift/truncation. 1.0 = pure ripple. Quality issue #8. |
| `audience`          | `"teenager"` | Age register the translator is steered toward: `child` / `teenager` / `adult`. Prompt-only softening — gentler wording, never a dropped or bleeped line. **The one `[pipeline.options]` key that participates in the cache key** (as a `|audience=<level>` suffix, so `adult` keys are byte-identical to pre-guardrail ones); it stays out of `config_hash` so the warm stage cache, keyed `(stage, candidate_id)`, is not fragmented. This is the default for `patmir dub` / `patmir submit`; the Chrome extension sends its own value on every submission and wins. ADR `2026-08-28-audience-age-guardrail`. |
| `prelude_window_seconds` | 40.0 | Watch-along only: seconds of the opening analyzed to establish the cast before playback. Smaller = faster first-audio, fewer characters seen up front. |

## How to swap a model

0. Decide whether the swap is for **every machine** (edit `[pipeline]`) or **one machine**
   (edit that machine's `[pipeline.profiles.<name>]`). Editing `[pipeline]` on a non-default
   machine is the thing profiles exist to prevent.
1. Add or enable a candidate in the relevant `[[stages.<stage>.candidates]]` (or legacy `[[eval.<stage>.candidates]]`) section of `patmir.toml`.
2. Change `[pipeline].<stage>` to the new candidate id.
3. Update this file's row + `docs/architecture/stages/<stage>/current.md` + the relevant model file in `docs/architecture/stages/<stage>/<model>.md`.
4. If the swap is non-trivial (different model family, different language coverage, etc.), add a new ADR in `docs/architecture/decisions/`.
